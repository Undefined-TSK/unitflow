1 · 项目定位与读者

PyPedia 是一个个人本地优先的 Python 知识助手。它把用户的资料库（官方文档、GitHub 仓库、离线文档、论坛）与对话上下文结合起来，用 RAG 检索 + 大语言模型生成，回答问题时做到：

① 记住你（Mem0 长期记忆）

抽取交互中的偏好 / 卡点 / 等级，跨会话留存；注入画像让回答贴合「你这个人」。

② 理解水平（L1–L5 等级适配）

零基础给比喻与逐行注释，专家给设计权衡与源码级结论，system 指令随等级变化。

③ 持续进化（Reflexion + Voyager）

沉淀技能库、复盘失败诊断；只进化 prompt / skill / 工具 / 语料，不微调权重。

④ 有凭有据（级联检索 + 置信度）

主源 / 补充源三级级联，答案附置信度拆解与双模型二审修订。

1.1 设计哲学

能用现成轮子就不自己造。RAG、切分、检索、记忆、重试、日志、解析、CLI 全部用成熟外部库；仅保留纯产品逻辑（等级适配、级联主辅判别、长上下文规划、二审提示词、进化薄层、FastAPI、前端 UI）自写。
信条在本项目中的落实
万物皆对象manifest 是类的定义（form=template 开发侧通用 / form=instance 成品开箱即用），安装实例化后的运行体是对象，各自持有独立 profile 五维状态；团队本身也是一个对象（§5.14.1）
万物皆插件内核即注册表、注册表即内核：23 项内置能力的唯一真值源是 Unit manifest，PluginRegistry 是 UnitRegistry 的兼容子类；市场安装与编辑器导出走同一契约（§5.13）
图就是引擎GraphRuntime 直接解释执行节点图，无独立 AgentLoop；模型调用是图中唯一的 LLM 节点，确定性步骤皆图节点，judge 出边 condition 实现分支与循环（§4、§5.13）；图有两态——画布呈现态与 node_graph 契约态可双向编译、动态同步；嵌套图（Agent 内部图 + 团队图）表达「独立却相互联系」（§5.14）
轻量单机桌面单用户、零服务进程（LanceDB/qdrant 本地模式）；框架选型以「不添负担」为准——CrewAI/LangGraph/Workflows 复评均为负压缩，保持线性管道
恒等 · 无折扣重构不得改变行为：规则引擎关闭即旁路恒等；单 Agent 图封装与旧架构产出一致性经真实测试①逐项比对（检索命中/首要证据/置信度/阶段产物/记忆与自进化节点）
测试逼真三层验收：零真实 LLM 的 741 项单测（打桩隔离）→ 真实子进程/浏览器级 e2e → 真实 LLM 的一致性/全链路测试；测试必须能逼出真 bug（ref 三处漂移、linkdot 连线失效、画布塌缩、confidence import 错误均为测试逼出后修复并锁定回归）
降级不崩主流程任何一步失败都有兜底：检索退空、摘要退化截断、MCP 降级、LLM 不可达降级 Mock、置信度评估失败给 55 分——主流程永不因单点失败中断

可落地交付即可复制运行：无伪代码、无占位逻辑、依赖锁版本、运行命令与预期输出齐备
极简交付过程文档精简合并为唯一说明书；任务清单闭环后才进入下一阶段；不重复已验证的劳动

5 · 核心模块详解

每个模块统一按「职责 / 位置 / 输入·输出 / 关键逻辑 / 依赖轮子 / 相关配置」描述。

5.1 等级适配 pypedia/levels.py

  • 位置：输入之后、检索之前。输入：等级 1–5 + 问题。输出：深度指令 system prompt。
  • 逻辑：L1 零基础（比喻+逐行注释）→ L5 专家（设计权衡+源码级结论）。纯产品逻辑，无现成轮子，保留自写。

5.2 级联检索 RAG pypedia/rag.py + retrieval/

  • 位置：核心检索。输出：带 main / supplement_a / supplement_b 角色标注的片段。
  • 轮子：LanceDBVectorStore 持久化、SentenceSplitter 统一切分、QueryFusionRetriever 混合检索、每角色独立 table。BM25 tokenizer 已换 jieba。
  • 配置：TOP_K_PER_STAGE=3、FETCH_TIMEOUT=6。

5.3 本地重排 pypedia/rerank_local.py

  • 位置：检索之后、生成之前（精排三级链第二级）。
  • 轮子：BAAI/bge-reranker-base（1.1GB）懒加载、后台线程预热；HF_ENDPOINT 走国内镜像；RERANK_LOCAL_ENABLE=false 只用向量分数。

5.4 长上下文管理 pypedia/conversation.py

  • 位置：检索之后、生成之前，与等级适配并行。
  • 逻辑：estimate_tokens（CJK 1 字=1、英文≈1.3×1.2、+4 消息开销）→ ContextPlan（滑窗保留最近 CONTEXT_KEEP_TURNS=4 轮 + 更早滚动摘要）→ 摘要超 CONTEXT_TOKEN_BUDGET//3 二次截断。摘要失败退化截断拼接，主流程永不阻塞。
  • 配置：CONTEXT_TOKEN_BUDGET=6000、CONTEXT_KEEP_TURNS=4、CONTEXT_SUMMARY_TRIGGER=8。

5.5 分步推理（MCP） pypedia/mcp_client.py

  • 位置：生成之前，复杂问题（多问号/并列词/流程词启发式）触发 sequential-thinking 便笺。
  • 客户端：stdio_client 起子进程 → ClientSession 手动 __aenter__ + initialize() 保长连接 → run_forever() 保活（用 run_until_complete 协程永不执行）。
  • 环境：显式传 PATH/HOME（MCP 安全模型，子进程不继承环境）；每 server 5s / 总 25s 优雅关闭。
  • 配置：MCP_ENABLE、MCP_FS_DIR、MCP_FETCH_ENABLE、MCP_THINKING_ENABLE。

5.6 答案二审 pypedia/review.py

  • 位置：生成 + 置信度之后。独立审阅通道，temperature=0。
  • 逻辑：输入 (query, answer, evidence)，输出 {verdict: pass|revise, notes, revised}；revise 无修订版降级 pass；无证据不硬审。审阅模型可用 REVIEW_MODEL 覆盖（如 qwen-max）。
  • 配置：REVIEW_ENABLE、REVIEW_MODEL。

5.7 置信度 models/dashscope.py:evaluate_confidence

qwen-plus 对照证据评估；decision-model-preview 为预留入口（未开通自动降级 chat）。维度口径：主源命中 55 + 跨源一致 30 + 新鲜度 15（由模型终评，非自写公式）。

5.8 记忆 / 画像 memory_store.py + memory/session.py

  • Mem0 全权负责抽取 / 去重 / 冲突解决；profile_prompt(query) 语义检索注入相关画像（非全量倾倒）。
  • 无百炼密钥时优雅降级「无记忆」模式。会话级 Session.context 持 ConversationContext（懒加载）。

5.9 自进化 evolution/

  • Reflexion（内循环）：reflexion.py 失败诊断写 JSON buffer，recent()/summary() 注入 prompt。
  • Voyager（外循环）：voyager.py skill 库（name/trigger/action），infer_from_session 从会话画像自动归纳。
  • 杠杆仅四个：prompt / skill / 工具列表 / 检索语料——不微调权重。

5.11 Web 服务 app.py

  • 28 个 API 端点 + 根 HTML 页面（详见第 6 章）。
  • 中间件链（Starlette「后注册在最外层」）：request_log（最外，记全部请求含 401）→ auth_guard（内，Bearer 校验，放行 / / /static / /api/status）。
  • /api/ask 经 AskLimiter 配额门（并发信号量 + 60s 滑窗速率，429 + Retry-After）。

5.12 前端 static/

5.14.1 设计思想总纲

思想内涵在本项目的落地
① 对象与类用「类 / 对象」理解一切 Unit：manifest 是类的定义，安装实例化后的运行体是对象。类定义可复用、可定制；对象各自持有自己的状态manifest form 字段：template = 类（开发侧通用定义，待定制）/ instance = 对象（成品，已配置开箱即用，仅需填环境项）；两类均可上架市场，安装即「new 出一个对象」（§5.13）

设计哲学要点（最新口径，四思想合一）：① 万物皆对象——manifest 是类（form=template）、安装/实例化是对象（form=instance），团队本身也是一个对象；② 万物皆插件——内核即注册表，23 项内置 + 市场单元走同一契约；③ 图就是引擎——GraphRuntime 直接解释执行 node_graph，模型调用是唯一 LLM 节点；④ 图两态双向编译——画布呈现态 ↔ node_graph 契约态互为投影、动态同步，ComfyUI UI/API 双格式与 Blockly JSON round-trip 是工业级先例；⑤ 每团队每 Agent 独立 profile——五维隔离互不影响，联系的是数据流不是状态池；⑥ 恒等无折扣——图封装与旧架构产出一致性经真实测试逐项比对。

5.14.3 流程图：三大结构 + ISO 5807 符号标准

1966 年 Böhm 与 Jacopini 证明结构化程序定理：任何适当算法都可以分解为顺序、选择（if-then-else）、循环（while-do）三种控制结构。项目图运行时把三结构落为原子规则：

三结构齐备即图灵完备的表达力下限：确定性步骤（process/plugin 节点）承载「做什么」，judge 分支承载「往哪走」，模型调用是图中唯一的 LLM 节点——「全管线即一张图」由此成立。

符号标准：ISO 5807（源自 1970 ANSI 标准）定义了全套流程图符号，形状本身就是语法。核心五符号（覆盖 90% 场景）：椭圆/圆角=起止（terminator）、矩形=过程（process，一框一步）、菱形=判断（decision，唯一允许多出口的符号，每条出边必须标注条件 Yes/No）、平行四边形=输入/输出（data，数据跨越边界）、箭头=流向（flowline，约定自上而下、自左而右；交叉不即汇合，汇合须有汇流符号）。完整 22 符号按家族分组：

ISO 5807 五条绘制规则（项目画布同源遵守）：① 一致性——同一份图内相同形状必须永远代表相同含义；② 简洁性——单图建议不超过 15~20 步；③ 方向正确——箭头反映真实流向，不得已交叉时用跳线区分；④ 选符精确——涉及判断必须用菱形，禁止矩形加「是否?」冒充；⑤ 颜色有规则——同类同色，总数不超 4~5 色。

项目取舍：流程图家族里，项目落地了其中四个——起止（entry/exit）、过程（process/plugin）、判断（judge，出边带 condition 即 Yes/No 标注）、预定义过程（plugin 节点 ref 引用 unit，与「子流程引用」同思想）；存储家族由 profile 目录与知识库承担（非图内符号）；页内/页间连接器由「图内回指边 + 嵌套图两层引用」承担。**判断菱形是流程图中唯一的多出口符号**——这正是 judge 节点设计的直接来源。

Nassi-Shneiderman 盒图（1972，别名结构图；相关标准 DIN 66261）：完全去掉带箭头流程线，整个算法写在一个矩形框内、框内嵌子框，无 goto 表示手段。与流程图对比：功能域一目了然、与代码距离近，但 goto/break/continue 无法表示、修改需重画。对项目的启示：盒图是「呈现态=树形嵌套、契约态=嵌套 JSON」的天然同构先例——画布可提供盒图视图作为流程图画布的受约束投影（禁 goto 子集，供教学/审查态），完整流程图画布作为超集保留逃生舱。

UML 活动图并行语义（UML 2.x，Petri 网启发的 token 流语义——节点在其所需 token 全部到达时才「点火」）：Fork（粗横条，复制 token 并发推进）/ Join（粗横条，等待所有入边后发出单一 token）/ Merge（菱形，token 直通不等待不同步，禁止用于同步并发流）/ Decision（菱形，guard 互斥完备，至多一条 [else]）。经典错误：用 merge 闭合 fork——逐 token 放行导致后续节点每分支各执行一次；正确铁律是 fork 用 join 闭合、decision 用 merge 闭合。双终止节点：Activity final（牛眼，终止整个活动杀所有 token）vs Flow final（圆内叉，仅灭所在分支）。泳道（Activity Partition）按责任方分区，跨区边即责任移交——与「团队图节点引用成员 Agent」同思想。项目当前 judge + 回边已覆盖顺序/选择/循环；Fork/Join 并行语义列为演进项（P8），契约预留双终止与 guard 互斥完备约束。

② 核心语义一：字段（Fields）—— 懒求值的「函数式数据」（官方手册 fields.html）：

  • 字段本质是函数：把任意数量输入变换为单值，可对不同输入数据多次求值——同一字段接到不同几何上，结果逐元素而变（Random Value 接 Scale，每个实例缩放不同）。
  • 三态插槽（socket shape 即类型系统的一部分）：圆形=必须单值，不能接字段（输出则恒为单值）；菱形=可接字段、可输出字段；菱形带点=可为字段但当前是单值（每元素同值，Socket Inspection 显示具体值）。
  • 三类节点：数据流节点（几何进几何出，真改数据）+ 字段节点（菱形插槽，按元素逐点求值的「指令」）；字段节点再分输入节点（Position / ID / 端点选择——脱离上下文无意义）+ 函数节点（Math / 几何接近）。
  • 字段上下文：字段求值语境 = 几何组件类型 + 属性域；同一字段子树在不同数据流节点下求值结果不同（第一个 Set Position 改过的位置，第二个再求值就是新位置）。要「冻结」中间值用 Capture Attribute（存为匿名属性）。
  • 可视化约定：字段连线画虚线，单值连线画实线，接错画红色实线；取单值用 Sample Index / 属性统计。

10 · 知识库与预装资料源

10.1 支持的文件格式

PDF（pypdfium2）、DOCX（mammoth）、EPUB（ebooklib）、PPTX（python-pptx）、XLSX（openpyxl）、HTML/网页（trafilatura）、Markdown。上传经流式大小检查 + ZIP 炸弹 100:1 检测 + 解析线程池 120s 超时墙。

10.2 三级级联的角色定义

  • main（主要）：用户指定的库官方主站文档——答案以主源为准。
  • supplement_a（补充 A）：GitHub 文档与源码——佐证与边界场景。
  • supplement_b（补充 B）：离线文档 + 权威论坛——补充边界。

10.3 预装权威资料源（默认即开箱可用）

data/preset_sources.json 预置 9 项：Python 官方文档（教程/内置/asyncio/语言参考）、CPython 官方 GitHub 仓库、官方论坛（discuss.python.org）、StackOverflow 等。特点：

  • 双开关：PRESET_SOURCES_ENABLE（总闸）+ ENABLE_WEB_FETCH（抓取闸）。离线（抓取关闭）下不污染知识库，内置 corpus.json 仍兜底。
  • 幂等 + 隔离：首次启动后台 daemon 真实抓取；单源失败不影响其余源、绝不阻塞启动；清单 filelock 原子替换。
  • 可编辑：不硬编码，可在设置页 / CLI 一键 preset-import 或编辑 JSON 增删来源。

12.2 新增 MCP server

  • 在 mcp_client.py 增加 server 启动与 client session；在 capabilities/__init__.py 登记开关（含真实连接探测）。
  • Node server 需 npx；Python server 需对应包。起不来只降级该项。

12.3 新增知识来源类型

继承 ingest/strategies.py 的 IngestStrategy，实现「抓什么 / 怎么失败降级」即可，共享流程（角色归一、文档组装、清单登记、索引写入与块数回填）已上提。参考 UrlStrategy / GithubStrategy / FileStrategy。

12.4 新增 API 端点

在 app.py 增加路由；若需鉴权，确保中间件链顺序正确（request_log 最外、auth_guard 内层）；若涉及费用，挂到 AskLimiter 配额门。

  1. mcp 2.x 与官方 fetch server 互斥：fetch server 锁 mcp<2,>=1.29，且异常类名不同（McpError vs MCPError）→ 选 mcp 1.30.0 全家桶。
  2. LanceDB 替 chroma 迁移 bug：旧迁移代码找三张表但实际单 collection（role 在 metadata）→ 按 metadata 分组重迁（9 节点无损）。
  3. highlight.js 11 npm 不再预构建浏览器包 → 从 cdnjs 下载官方构建。
  4. KaTeX auto-render 仅 .ts 源码 → 手写 renderMath（TreeWalker + katex.renderToString）+ 货币防误伤启发式。
  5. run_until_complete 事件循环停转 → MCP 客户端必须 run_forever() 保活。
  6. 百炼 rerank 响应结构：实测 output.results（旧文档写 data.rerank 会 KeyError 静默降级），已修双路径。
  7. 能力开关误判关闭：os.getenv 读不到 Settings 默认值 → 统一改走 settings。
  8. mem0 2.2.1 契约变更：禁用顶层 user_id，search 的 limit 更名 top_k（旧调用被 except 静默吞致记忆恒空，已修）。
  9. mem0 qdrant 细节：insert 的 vectors 是「向量的列表」而 search 是扁平向量；id 须合法 UUID。
  10. Starlette 中间件顺序：最后注册的最外层——request_log 注册在 auth_guard 之后，401 才被日志记录。
  11. 前端 script 拆分 TDZ：经典 script 共享全局但 let/const 有临时死区，共享状态须前置 util.js。
